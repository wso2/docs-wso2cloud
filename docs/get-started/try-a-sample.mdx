# Try the Customer Support Agent sample

**Customer Support Agent** is a sample AI agent that answers questions about products, stock availability, and store policies for a demo outdoor gear store.

Deploy it to explore how agents use MCP servers and APIs to access business data, and how Choreo Cloud brings these components together.

## Try the sample

The sample has three components: an agent, an MCP server that gives the agent its tools, and an API that holds the store's data.

- **Customer Support Agent** is deployed in Choreo Cloud as a managed agent in Agent Management.
  - An LLM provider for Anthropic, OpenAI, Gemini or Mistral is registered in Choreo Cloud, so the agent accesses the LLM through the AI gateway, where it can be governed by guardrails.
- **Products MCP server** is defined as an Integration in Choreo Cloud which will expose the product data to be consumed by the agent.
  - When you deploy the sample, it is added to Agent Management as an MCP proxy, so the agent accesses it through the same gateway.
- **Products API** is a REST API that will provide product data. Usually this is a third-party system that sits outside Choreo Cloud, which can be exposed within the cloud as a managed API. In this sample, it is a mock API deployed in Integration.

To deploy and try the sample:

1. Ensure you have the following requirements:
   - A [Choreo Cloud organization](./sign-up.mdx).
   - An LLM provider for Anthropic, OpenAI, Gemini or Mistral in Agent Management. If your organization doesn't have one, the console asks you to create it during the sample deploy. To create the provider, you need an API key from [Anthropic](https://platform.claude.com/docs/en/get-api-key), [OpenAI](https://developers.openai.com/api/docs/quickstart), [Google AI Studio (Gemini)](https://aistudio.google.com/docs/api-key) or [Mistral](https://docs.mistral.ai/getting-started/quickstarts/studio/activate-and-generate-api-key).

2. In the [Choreo Cloud console](https://console.cloud.choreolabs.com), create a project, or open one that's empty.

3. In the **Try a sample** card, deploy the sample in one of two ways:
   - Select **Deploy sample**, and the console deploys the three components for you.
   - Select **Ask Choreo Agent to deploy**, and Choreo Agent deploys them, guiding you through each step.

4. When the deploy is done, open the **Customer Support Agent** in Agent Management.

5. In **Try It**, ask the agent about the store. For example:
   - Which tents do you sell, and how are they different?
   - Is the Summit 2 Tent in stock?
   - What's the warranty on a backpack?
   - Do I get free shipping on a USD 60 order?

The sample's source code is available on [GitHub](https://github.com/wso2/cloud-samples/tree/master/customer-support-agent).

## Prepare an agent for production

Before an agent goes to production, consider the following aspects:

- **What the agent can do** should be limited to the models and tools it needs. In Agent Management, you can attach LLM providers and MCP servers to each agent, behind a gateway with access control and rate limits. The LLM provider's key stays in the platform, not in the agent code.
- **What the agent does** should be visible, because an agent decides its own steps. Agent Management records each run as a trace, with every LLM call, tool call, and MCP request, so when an answer is wrong, you can see the step that went wrong. See [Observability](https://choreolabs.com/agent-platform/docs/cloud/concepts/observability/).
- **How well the agent performs** needs to be measured, because an answer can look right and still be wrong. Evaluators score the agent's runs on accuracy, safety, reasoning, and tool use, so you can find a drop in quality before your users do. See [Evaluation](https://choreolabs.com/agent-platform/docs/cloud/concepts/evaluation/).
- **Guardrails** stop the requests and answers that should never pass. You can set them on an LLM provider, so they apply to every agent that uses it, with no change to the agent code. See [Add guardrails to your agent](https://choreolabs.com/agent-platform/docs/cloud/tutorials/govern-the-model/).
- **The information the agent uses** already sits in your APIs and services. For example, you can build MCP servers in Integration that provide the information agents need, so you don't need to build new services for the agent.
