# Glossary

| Term | Definition |
| --- | --- |
| **Alert** | A notification sent when an alert rule's condition is met. Every alert is recorded in the alert history. |
| **Alert rule** | A condition on a component's CPU usage, memory usage, or logs, checked on a schedule in each environment the component is deployed to. |
| **Cloud data plane (CDP)** | Shared, multi-tenant runtime infrastructure that WSO2 runs. Components from many organizations run in it, isolated from each other. |
| **Component** | A single unit you build, deploy, and run, such as an agent, an integration, or an API. Each service uses its own names for its components. Each component belongs to one project. |
| **Control plane** | Where you manage your organization, users, and resources. WSO2 runs it as SaaS. |
| **Data plane** | Where your workloads run and your runtime traffic flows. It can be a cloud data plane or a private data plane. |
| **Deployment track** | A separate line of a component, such as one per branch or API version, that is built and deployed alongside the component's **default** track. Each deployment track has its own alert rules, and also runs the default track's rules. |
| **Enterprise sign-in** | Signing in to WSO2 Cloud with your organization's own OpenID Connect identity provider instead of Google or GitHub. |
| **Environment** | An isolated place where components run, such as Development or Production. Shared across services, except Platform Engineering. |
| **Group** | A set of users in an organization. Each group is granted a role, and its members get that role's permissions. Every organization has one built-in group per role, with the same name. |
| **Notification channel** | A webhook or a list of email addresses that receives alerts from one environment. Each environment has a default channel. |
| **Organization** | The top-level tenant boundary in WSO2 Cloud. It holds users, service contacts, and the resources you create in every service. |
| **Organization handle** | A unique, readable identifier derived from the organization name, shown with an `@` prefix. |
| **Organization Unit ID** | A unique, system-generated identifier for an organization. |
| **Private data plane (PDP)** | Runtime infrastructure dedicated to a single organization. It can run in WSO2's cloud account, your cloud account, or your data center. |
| **Private endpoint** | A host and port in your own network, such as a database, that workloads reach through private network access. |
| **Private network access** | An outbound tunnel from one environment to your Tailscale network, so workloads in allowed projects can reach private endpoints. |
| **Project** | A group of components that make up one application or domain. Shared across services, except Platform Engineering, so one project can hold components from several services. |
| **Role** | A set of permissions, granted to a group. WSO2 Cloud has five built-in roles: Admin, Platform Engineer, Developer, Viewer, and API Publisher. They apply across the organization and in every service. |
| **Service** | A part of the WSO2 Cloud platform that covers the full lifecycle of one kind of work, including governance, such as Agent Management or API Management. Every service is part of the WSO2 Cloud console and has its own documentation. |
| **Service contact** | A person WSO2 notifies about general announcements, security, or billing for an organization. |
| **Subnet router** | A Tailscale device in your network that forwards tailnet traffic to the address ranges it advertises. |
| **Subscription** | The plan an organization is on for a service. It sets features, limits, and how usage is billed. |
| **Tailnet** | Your private Tailscale network. Private network access joins the gateway to it. |
| **User** | A person who belongs to an organization. |
